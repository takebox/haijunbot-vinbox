# 2. Quick Start

This chapter will guide you on how to quickly install, configure, and start using HaijunBot, embarking on your journey with an intelligent AI assistant.

## 2.1 System Requirements

- **Operating System**: Linux (primary), Windows 10/11 (WSL or native, with GUI automation support).
- **Python Version**: Requires Python 3.12.
- **Docker** (optional): Supported for use via a Docker image, with no need to install the Python/Rust environment locally.

## 2.2 Installation

We provide two installation methods: a one-click installation script (recommended) and manual installation.

### One-Click Installation (Recommended)

To simplify the installation process, we provide a one-click installation script that automatically handles all dependencies and configuration. Just run the following command in your terminal:

```bash
# GitHub (recommended)
bash -c "$(curl -fsSL https://raw.githubusercontent.com/takebox/HaijunBot/main/scripts/quick-install.sh)"

# Or use the Gitee mirror (faster access within China)
bash -c "$(curl -fsSL https://gitee.com/takebox/HaijunBot/raw/main/scripts/quick-install.sh)"
```

The script performs the following actions:

1. Preferentially fetches the HaijunBot source code corresponding to the latest tag, and uses a shallow clone to reduce download size.
2. Automatically installs `uv` (if not already installed on the system).
3. Installs HaijunBot using `uv tool install -e . --python 3.12`.
4. Optionally installs tools that improve the experience, such as `rg`, `fd`, `fzf`, `tmux`, and `tree`.

> **Tip**: The script preferentially tries the latest tag on GitHub; if it cannot be fetched, it falls back to Gitee or the default branch.
>
> The script automatically installs `uv`, so no manual preparation is needed.

### Manual Installation

If you prefer more control over the installation process, you can choose manual installation.

#### Install from Source

```bash
# 1. Clone the source code of the latest release version
# Replace <latest-tag> with your target tag
git clone --depth 1 --branch <latest-tag> https://github.com/takebox/HaijunBot.git

# 2. Enter the project directory
cd HaijunBot

# 3. Add the repository's bundled dependency directory to PATH (the current repository already bundles x86_64_linux)
export PATH="$(pwd)/src/haijunbot/haijunbot_data/deps/x86_64_linux:$PATH"

# 4. Install the project and additional tools using uv
uv tool install -e . --python 3.12
uv tool install playwright
uv tool install ddgr
```

> **Tip**: After installing with `uv tool install -e . --python 3.12`, any changes you make to the source code take effect immediately, which is ideal for developers.
>
> If there is no corresponding bundled dependency directory for your current platform, first install `uv` manually, or switch to a version that bundles the dependencies for that platform.

#### Other Methods

Methods such as PyPI, installing directly from Git with `uv`, and Docker are still available for specific scenarios, but the main installation entry point has been unified as "source download + repository-bundled `uv` + `uv tool` installation". For container-based approaches, please refer to the relevant deployment documentation.

Using a Docker image avoids local environment configuration, as all dependencies are pre-installed. The image has been published to GitHub Container Registry (GHCR), **publicly available with no login required**.

**Pull the image from GitHub Container Registry:**

```bash
# Pull the latest version
docker pull ghcr.io/takebox/haijunbot:latest
```

> **Tip**:
>
> - The image is public by default and can be pulled without logging in
> - Each time a new version is released, multiple tags are automatically generated: `latest`, `v1.0.0`, `1.0`, `1`, etc.
> - It is recommended to use the `latest` tag to get the latest version

**Use Docker Compose (recommended):**

The Docker Compose configuration uses a **non-root user** (the haijunbot user, UID 1000) by default to avoid file permission issues:

```bash
# Run the container (using the pre-built image, no local build required)
docker-compose run --rm haijunbot
```

> **Note**:
>
> - The container runs as the haijunbot user (UID 1000); the GID can be set via the `GID` environment variable (default 1000), and it is recommended to set it to the current user's group ID to avoid file permission issues
> - Files created inside the container belong to the haijunbot user; if the GID matches the host group, they can be accessed directly from outside without adjusting permissions
> - Configuration files (`.haijunbot` and `.gitconfig`) are automatically mounted to the user's home directory inside the container

**Use Docker Commands Directly:**

```bash
# Run as the current user (recommended, avoids permission issues)
docker run -it --rm \
  --user "$(id -u):$(id -g)" \
  -v $(pwd):/workspace \
  -v $HOME/.haijunbot:/home/haijunbot/.haijunbot \
  -v $HOME/.gitconfig:/home/haijunbot/.gitconfig:ro \
  -w /workspace \
  ghcr.io/takebox/haijunbot:latest
```

> **Tip**:
>
> - The Docker image comes with all tools pre-installed (Python 3.12, Rust, Clang, Fish shell, etc.), ready to use out of the box
> - After the container starts, it automatically enters the fish shell with the virtual environment already activated
> - Using `-v` to mount directories makes it convenient to work with local code inside the container
> - **Using a non-root user is recommended** to avoid file permission issues; files created inside the container can be accessed directly on the host
> - Mounting `.gitconfig` preserves your Git user information, making it convenient to use Git inside the container
> - Using Docker Compose is the simplest approach, automatically handling user permission configuration and file mounting
> - It is recommended to use the pre-built image on GHCR directly, with no local build required

## 2.3 First Run and Configuration

After installation is complete, when you run any `haijunbot` command for the first time (such as `hjb`), if the configuration file does not exist, the system creates a default configuration file `config.yaml` in the `~/.haijunbot/` directory.

### 2.3.1 Interactive Configuration Wizard (Recommended)

To quickly complete configuration, we provide an interactive configuration command `hqc` (haijunbot-quick-config), which guides you step by step through the following operations:

```bash
# Run the interactive configuration wizard
hqc
```

The wizard guides you through:

1. **Select an AI Platform**: Choose the OpenAI or Haijun platform.
2. **Enter Credentials**: Enter the API base URL and API key.
3. **Select a Model**: Automatically fetch the list of available models for you to choose from.
4. **Configure Model Groups**: Choose appropriate models for different usage scenarios (Normal/Smart/Cheap).
5. **Test the Connection**: Test API connectivity to ensure the configuration is correct.
6. **Save the Configuration**: Automatically save the configuration to `~/.haijunbot/config.yaml`.

The entire process requires no manual editing of configuration files, greatly simplifying the initial setup.

**Skipping Interactive Configuration**:

If you use HaijunBot in a CI/testing environment, you can skip the interactive configuration wizard by setting the environment variable `HAIJUNBOT_SKIP_INTERACTIVE_CONFIG`:

```bash
export HAIJUNBOT_SKIP_INTERACTIVE_CONFIG=1
```

After setting this environment variable, HaijunBot will not automatically start the configuration wizard, but will directly use the default configuration or an existing configuration file.

### 2.3.2 Manual Configuration (Optional)

If you prefer to manage the configuration file manually, or need to perform more complex settings, you can also skip the interactive wizard.

#### 1. Generate the Default Configuration File

The first time you run any `haijunbot` command (for example `hjb` or `hpm info`), if
`~/.haijunbot/config.yaml` does not exist, the system first attempts to start the interactive wizard. You can directly
press `Ctrl+C` to exit the wizard, and then a default configuration file will be created.

#### 2. Obtain Platform Credentials

You need to manually obtain the credentials for the chosen platform. The specific methods are as follows:

- **OpenAI**: Obtain your `OPENAI_API_KEY` and `OPENAI_API_BASE`
  (if using a proxy).
- **Haijun**: Obtain your `JUGLOW_API_KEY` and `JUGLOW_API_BASE`
  (if using a proxy).

#### 3. Edit the Configuration File

Open `~/.haijunbot/config.yaml` and fill in your credential information.

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/takebox/HaijunBot/main/docs/schema/config.schema.json

# ====== Basic Configuration ======
# Set the model group to use by default
llm_group: default

# ====== Model Group Configuration ======
# You can define multiple model groups and switch between them via llm_group
llm_groups:
  default: # Default model group
    normal_llm: gpt-5 # References a model defined in llms below
    # Optionally configure a cheap model and a smart model
    # cheap_llm: gpt-3.5-turbo
    # smart_llm: gpt-5

# ====== Model Definitions ======
llms:
  gpt-5:
    platform: openai # Platform type
    model: gpt-5 # Model name
    max_input_token_count: 128000 # Maximum model input token count

    # Model-specific configuration (llm_config)
    llm_config:
      openai_api_key: "your-api-key-here" # Replace with your API key
      openai_api_base: "https://api.openai.com/v1" # API base address, can be used for a proxy
      openai_extra_headers: '{"X-Source": "haijunbot"}' # Extra HTTP headers (optional)
```

> **Note**: Newer versions recommend the `llm_groups` and `llms` configuration approach, which provides more flexible model management. The `ENV` configuration method is still supported, but migrating to the new configuration approach is recommended.
>
> **Tip**: API Keys support configuring multiple keys for round-robin use. In `llm_config`, you can use the list format `["sk-xxx1", "sk-xxx2"]` or a comma-separated string `"sk-xxx1,sk-xxx2"`; the environment variable supports the comma-separated format `OPENAI_API_KEY=sk-xxx1,sk-xxx2`.

After saving the file, your HaijunBot configuration is complete!

You can also open and edit the configuration file via `hjb -e` to change these options.

> **Note**: When running inside a Git repository, HaijunBot automatically detects this and switches to code development mode (hca).

## 2.4 Verifying the Installation

After configuration is complete, you can run the following command to verify whether HaijunBot has successfully connected to the AI platform:

```bash
hpm info
```

If the configuration is correct, it will try to connect to all AI platforms for which you have provided credentials in `ENV`,  
 and list all available models under each platform. This is an excellent way to verify whether all credentials are correct.  
 If one or more platforms fail to list models successfully,  
 go back and check the corresponding credentials in `config.yaml`.

> **Note**: Some platforms may list available models even if credentials are not configured correctly, but this does not necessarily mean the configuration succeeded.  
> To ultimately confirm whether the configuration is correct, the best approach is to try talking directly to the model,  
> for example using the `hpm chat -p <platform> -m <model>` command.  
> If you can converse successfully, that means the configuration is correct.

## 2.6 Using the Web Interface

In addition to the command-line interface, HaijunBot also provides a friendly web interface that supports interaction through a browser.

### Starting the Web Service

We provide a convenient startup command `haijunbot-service run`, which starts both the web gateway and the frontend service:

```bash
# Run in the project root directory
haijunbot-service run
```

The command performs the following actions:

1. Start the web gateway service (default port 8000)
2. Install frontend dependencies (automatically runs `npm install` on the first run)
3. Build the frontend release artifacts (`npm run build`)
4. Start the frontend release service (default port 5173)

> To start the frontend in development mode (hot reload, skip build), use `haijunbot-service run --dev`.

### Accessing the Web Interface

After startup is complete, you can access it through your browser:

- **Frontend Interface**: `http://127.0.0.1:5173`
- **Gateway API**: `http://127.0.0.1:8000`

### Environment Variable Configuration

You can customize the web service configuration via environment variables:

```bash
# Set the gateway password (optional)
export HAIJUNBOT_GATEWAY_PASSWORD="your-password"

# Set the gateway address and port
export HAIJUNBOT_GATEWAY_HOST="0.0.0.0"  # Default 127.0.0.1
export HAIJUNBOT_GATEWAY_PORT="8000"   # Default 8000

# Set the frontend address and port
export HAIJUNBOT_FRONTEND_HOST="0.0.0.0"  # Default 127.0.0.1
export HAIJUNBOT_FRONTEND_PORT="5173"   # Default 5173

# Then start the service
haijunbot-service run
```

### Stopping the Service

Press `Ctrl+C` in the terminal to stop all services.

> **Tip**: The web interface provides a visual operation experience, suitable for graphical interaction scenarios. The command-line interface is better suited for developers and automation scenarios.

Now you have completed all the setup; you can try running `hjb`, `hca`, or visiting the web interface to begin your first HaijunBot journey!
