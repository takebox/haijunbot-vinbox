# 7. Contributing

HaijunBot is an open, community-driven project, and we welcome and appreciate contributions in all forms, whether it's reporting bugs, submitting new features, improving documentation, or sharing your experience. This chapter provides you with a detailed guide to contributing to the project.

## 7.1 Contribution Workflow

We use the standard Fork & Pull Request workflow. HaijunBot has mirror repositories on both GitHub and Gitee, and you can choose either platform to contribute:

- **GitHub**: <https://github.com/takebox/HaijunBot>
- **Gitee**: <https://gitee.com/takebox/HaijunBot>

1. **Fork the repository**: First, visit the HaijunBot repository page on your preferred platform (GitHub or Gitee), click the "Fork" or "Forked From" button to copy the project to your own account.

2. **Clone your fork**: Clone your forked repository to your local machine.

   ```bash
   git clone https://github.com/YourUsername/HaijunBot.git
   cd HaijunBot
   ```

3. **Create a feature branch**: Create a new branch for your changes. Please use a meaningful branch name, for example `feature/add-new-tool` or `fix/resolve-issue-123`.

   ```bash
   git checkout -b feature/your-amazing-feature
   ```

4. **Make your changes**: Make your code or documentation changes on this new branch.

5. **Commit your changes**: After finishing your changes, commit them. We recommend using `haijunbot-git-commit` (`hgc`) to generate a conforming commit message.

   ```bash
   git add .
   hgc
   # Or commit manually
   # git commit -m "feat(scope): your commit message"
   ```

6. **Push to your fork**: Push your feature branch to your forked repository on GitHub.

   ```bash
   git push origin feature/your-amazing-feature
   ```

7. **Create a Pull Request (PR)**: Open your fork repository page on GitHub, switch to your feature branch, and click the "New pull request" or "Compare & pull request" button. Fill in the title and description of the PR, clearly explaining what you changed and why, and then submit it.

The project maintainers will review your PR and may suggest some changes. Once your PR is accepted, it will be merged into the main branch.

## 7.2 Coding Standards

- **Code style**: We follow the PEP 8 Python style guide. Please make sure your code conforms to this standard. We recommend using tools such as `black` or `autopep8` to automatically format your code.
- **Type hints**: Please add type hints (Type Hinting) to all function definitions and variables, as this helps improve the readability and robustness of the code.
- **Docstrings**: Please write clear docstrings for all public modules, classes, and functions, explaining their functionality, parameters, and return values.

## 7.3 Commit Message Guidelines

To keep the Git history clear and traceable, we require commit messages to follow the **Conventional Commits** specification. This is also why we strongly recommend using `hgc`.

The format of a commit message is as follows:

```text
<type>(<scope>): <subject>
<BLANK LINE>
[optional body]
<BLANK LINE>
[optional footer]
```

- **type**: Must be one of the following:
  - `feat`: Introduces a new feature
  - `fix`: Fixes a bug
  - `docs`: Documentation-only changes
  - `style`: Changes that do not affect the meaning of the code (formatting, semicolons, etc.)
  - `refactor`: Code refactoring that neither fixes a bug nor adds a feature
  - `perf`: A change that improves performance
  - `test`: Adds or modifies tests
  - `chore`: Changes to the build process or auxiliary tools
- **scope**: (optional) Indicates the scope affected by this commit (for example `tool`, `agent`, `docs`).
- **subject**: A short description of the purpose of this commit, no more than 50 characters.

Thank you for contributing your valuable time and talent to the HaijunBot community!
