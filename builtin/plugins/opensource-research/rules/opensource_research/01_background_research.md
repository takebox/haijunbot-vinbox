# Project Background Research

## Research Goals

Comprehensively understand the origin, development history, community ecosystem, and project positioning of an open-source project, laying the foundation for subsequent in-depth research.

## Research Steps You Must Perform

### Step 1: Collect Basic Project Information

**Information that must be searched and collected:**

- Project name, official website, GitHub repository link
- Project license type
- Main maintainer information
- The project's star count, fork count, and number of contributors
- Time of the latest commit and activity level

**Information sources:**

- GitHub repository home page
- Project official website
- search_web to search basic project information

### Step 2: Research the Project's Origin and History

**Information that must be collected:**

- When and in what context the project was created
- The reason and original intent for launching the project
- Important milestones in its development history
- Version release history

**Keywords to search:**

- "[project name] history timeline"
- "[project name] origin story"
- "[project name] development history"
- "[project name] first commit"

**Information sources:**

- Project official blog or documentation
- The GitHub README and CHANGELOG
- search_web to search the project's history
- read_webpage to read the project introduction document

### Step 3: Analyze the Community Ecosystem

**Content that must be researched:**

- The composition of the core maintainer team
- Contributor activity analysis
- Community size and growth trends
- Main user groups
- Community governance model

**Keywords to search:**

- "[project name] community statistics"
- "[project name] contributors analysis"
- "[project name] governance model"
- "[project name] case studies usage"

**Information sources:**

- The GitHub Insights page
- Project community forum or mailing list
- search_web to search community analysis

### Step 4: Clarify the Project's Positioning and Application Scenarios

**Content that must be analyzed:**

- The project's core functionality and positioning
- Main target user groups
- Typical application scenarios
- The core needs it addresses
- Differentiated positioning relative to other projects

**Keywords to search:**

- "[project name] use cases"
- "[project name] target audience"
- "[project name] vs alternatives"
- "[project name] when to use"

**Information sources:**

- The Introduction section of the official documentation
- The project FAQ document
- User cases and success stories
- search_web to search application scenarios

### Step 5: Analyze the Project's Tech Stack

**Information that must be identified:**

- The programming languages used by the project
- The main frameworks and libraries it depends on
- Runtime environment requirements
- Type of technical architecture

**Information sources:**

- The GitHub repository's language statistics
- Project dependency files (package.json, requirements.txt, etc.)
- The technical requirements section of the official documentation

## Research Output Requirements

### Document Structure

**Document that must be produced:** `01_project_background.md`

**The document must contain the following sections:**

1. Project overview (basic information table)
2. Project origin and development history
3. Community ecosystem analysis
4. Project positioning and application scenarios
5. Tech stack overview
6. Reference list

### Content Quality Requirements

- **Must**: all information cites its source (link, document title)
- **Must**: present basic project information in table form
- **Must**: present the project's development history in timeline form
- **Must**: provide concrete data support (star count, contributor count, etc.)
- **Forbidden**: information based on guesses or rumors
- **Forbidden**: unverified subjective judgments

## Research Depth Check

After completing this stage of research, you must confirm:

- [ ] You can clearly explain the project's origin and motivation for creation
- [ ] You understand the project's main development stages and milestones
- [ ] You grasp the basic situation of core maintainers and the community
- [ ] You clarify the project's positioning and typical application scenarios
- [ ] You understand the project's basic tech stack
- [ ] All information has credible source citations

## Common Mistakes

**❌ Wrong approaches:**

- Thinking you understand the project background after only reading the README
- Ignoring community activity and governance model
- Not searching for the project's history and origin story
- Focusing only on technology and ignoring application scenarios

**✅ Correct approaches:**

- Collect information through multiple channels and cross-validate
- Use search_web to broadly search for relevant information
- Read official documentation, blogs, and community discussions
- Analyze specific usage cases and user feedback

## Advanced Research Suggestions

If the project has important historical documents (such as design document drafts or RFC discussions), you should consult:

- The GitHub Discussions or Issues records
- The project's design documents (docs/design/)
- Related technical blogs and talk videos
- Academic papers (if the project is based on academic research)
