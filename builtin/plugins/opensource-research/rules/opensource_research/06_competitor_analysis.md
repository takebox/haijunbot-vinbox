# Competitor Analysis

## Research Goals

Identify and compare similar open-source projects and technical solutions, analyze the strengths and weaknesses of each option, and provide a comprehensive comparison basis and recommendations for technology selection.

## Research Steps You Must Perform

### Step 1: Identify Similar Tools and Competitors

**Competitors that must be searched for and identified:**

- Other open-source projects that solve the same problem
- Commercial products with similar features
- Solutions in related technical fields
- Emerging alternatives

**Keywords to search:**

- "[project name] alternatives"
- "[project name] competitors"
- "[project name] similar tools"
- "[project name] vs [technology]"
- "[project name] open source alternatives"

**Information sources:**

- Comparison articles on technical blogs
- Recommendations for similar projects on GitHub
- Discussions in technical forums
- search_web to search for competitor information

### Step 2: Collect Basic Competitor Information

**Must collect for each competitor:**

- Project name and introduction
- Tech stack and architecture
- Community activity (star count, contributors)
- Main maintainers
- License type

**Information to search:**

- The GitHub repository homepage
- Official website and documentation
- The project README
- Maintainer information

### Step 3: Compare Core Features

**Feature dimensions that must be compared:**

- Completeness of core features
- Quality of feature implementation
- Specific feature differences
- Unique features and innovations

**Comparison and analysis methods:**

- Create a feature comparison table
- Mark each competitor's level of support (supported/not supported/partially supported)
- Identify strengths and gaps in features
- Analyze the design thinking behind the features

**Keywords to search:**

- "[competitor name] features"
- "[competitor name] comparison"
- "[project name] vs [competitor name]"
- "best tool for [use case]"

**Information sources:**

- The feature lists in the official documentation
- Comparison analysis on technical blogs
- User discussions comparing features
- read_webpage to read comparison documents

### Step 4: Compare Performance

**Performance metrics that must be compared:**

- Performance benchmark results
- Resource consumption
- Concurrency capability
- Response time
- Throughput

**Key research content:**

- The performance of each competitor in different scenarios
- Performance bottlenecks and room for optimization
- Applicable performance scenarios
- Official and third-party performance tests

**Keywords to search:**

- "[project name] benchmark"
- "[project name] performance"
- "[project name] vs [competitor name] benchmark"
- "best performance for [scenario]"

**Information sources:**

- Official benchmark reports
- Third-party performance reviews
- Performance analysis on technical blogs
- Performance discussions in the community

### Step 5: Compare Usability and Learning Curve

**Usability dimensions that must be compared:**

- Documentation quality and completeness
- Friendliness of the API design
- Richness of examples and tutorials
- Community support (Q&A, forums)
- Learning curve and onboarding difficulty

**Content to examine:**

- The quality of the quick start guide
- The clarity of the API documentation
- The friendliness of error messages
- The convenience of debugging and troubleshooting

**Keywords to search:**

- "[project name] getting started"
- "[project name] tutorial"
- "[project name] documentation quality"
- "easy to use [technology]"

**Information sources:**

- The quick start in the official documentation
- User tutorials and getting started guides
- Community Q&A discussions
- Usage experience on technical blogs

### Step 6: Compare Community and Ecosystem

**Ecosystem dimensions that must be compared:**

- Community activity and scale
- Number and quality of contributors
- Third-party plugins and extensions
- Integration and interoperability
- Enterprise-level support and cases

**Keywords to search:**

- "[project name] community"
- "[project name] ecosystem"
- "[project name] plugins'
- "[project name] integrations"

**Information sources:**

- The Community info on GitHub
- The project's plugin and extension lists
- Enterprise cases and success stories
- Community activity metrics

### Step 7: Analyze Differences in Applicable Scenarios

**Scenario differences that must be analyzed:**

- The scenario each competitor is best suited for
- Unsuitable scenarios
- Priority of scenario selection
- Advantages in special scenarios

**Key research questions:**

- Which competitor should be chosen in which scenario
- Applicability at different scales
- Applicability for different tech stacks
- Applicability for different teams

**Keywords to search:**

- "when to use [project name]"
- "[project name] vs [competitor name] use cases"
- "best tool for [scenario]"
- "[project name] production experience"

**Information sources:**

- User cases and production practices
- Technology selection articles
- Community experience sharing
- Expert advice and recommendations

### Step 8: Summarize Selection Recommendations

**Recommendations that must be provided:**

- Selection recommendations for different scenarios
- Reasons for choosing each competitor
- Scenarios that should be avoided
- Possibilities for mixed use

## Research Output Requirements

### Document Structure

**Document that must be produced:** `06_competitor_analysis.md`

**The document must contain the following sections:**

1. Competitor identification and overview
2. Core feature comparison
3. Performance comparison analysis
4. Usability comparison
5. Community and ecosystem comparison
6. Applicable scenario analysis
7. Selection recommendations
8. Reference list

### Content Quality Requirements

- **Must**: use comparison tables to clearly show differences
- **Must**: provide objective data support
- **Must**: analyze the reasons behind the differences
- **Must**: give concrete selection recommendations
- **Must**: all comparisons have source citations
- **Forbidden**: one-sided comparisons that ignore competitors' strengths
- **Forbidden**: subjective judgments based on personal preference

## Comparison Analysis Framework

### Feature Comparison Matrix

**Must include:**

- Feature list
- Each competitor's level of support
- Quality of feature implementation
- Uniqueness of features

### Multi-dimensional Scoring

**Suggested scoring dimensions:**

- Feature completeness (0-5 points)
- Performance (0-5 points)
- Usability (0-5 points)

- Community activity (0-5 points)
- Ecosystem (0-5 points)

### Scenario Matching Analysis

**Must include:**

- Applicability for small projects

- Applicability for specific tech stacks

## Common Mistakes

**❌ Wrong approaches:**

- Comparing only one dimension while ignoring other aspects
- Highlighting only your own advantages while ignoring competitors' strengths
- Not providing concrete selection recommendations
- Lacking objective data support

**✅ Correct approaches:**

- Compare comprehensively across multiple dimensions
- Be objective and fair, avoiding bias
- Provide clear selection recommendations
- Speak with data and facts

## Practical Tips

**In-depth research strategy:**

1. Create comparison tables to make differences clear at a glance
2. Look at users' migration experiences to understand switching costs
3. Read technology experts' selection recommendations
4. Follow the latest development trends of each competitor
5. Consider the project's future evolution direction
6. Combine with actual needs to give targeted recommendations
